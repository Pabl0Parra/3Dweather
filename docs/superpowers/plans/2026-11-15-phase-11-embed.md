# Phase 11: Embed Widget Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tide widget other sites can embed with an iframe, and a builder page that makes the snippet.

**Architecture:** One static page `/embed/tide` reads its options from the query string, fetches the station's monthly tide table (`tides/{path}.json`, already published) and draws the day's turns and a small chart in the station's time zone. The tables gain the station's `name` and `tz` so the widget needs nothing else. `/embed` is the builder: pick a place, pick options, see a live preview, copy the `<iframe>` code.

**Tech Stack:** Python (tide tables), Astro 7, TypeScript, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-14-same-sources-data-design.md` (§10 item 11; findings §10: "`/embed` Embeddable tide widget builder (iframe)").

## Global Constraints

- Static only: the widget fetches public files from the same origin; no API.
- The `station` parameter must match `^[a-z0-9-]+(/[a-z0-9-]+){2}$` before any fetch (no path tricks); everything from the query string or files is written with `textContent`.
- The widget links back to the station page (`target="_blank" rel="noopener"`) and credits "Tides by 3Dweather · not for navigation".
- Works at 280 px wide and in light or dark theme.

## Review Focus

1. **Bad or missing `station` parameter**: a plain message, no fetch.
2. **Table missing (404) or old files without `name`/`tz`**: a plain message, or the path as the name and UTC.
3. **A day with three turns or five**: the list and chart still fit.
4. **The viewer is in another time zone**: the widget shows the station's local day and times, labelled with the zone.
5. **Builder output**: the snippet is valid HTML with the chosen options, attribute values escaped.
